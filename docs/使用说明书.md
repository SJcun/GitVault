# GitVault 使用说明书

适用于当前 V1 Windows 版本。按界面实际按钮编写。

**先记住：开始工作前，把 U 盘里的更新拉下来；工作结束后，先提交代码，再推送到 U 盘。**

| 你现在想做什么 | 从这里开始 |
| --- | --- |
| 第一次把现有项目放到 U 盘 | 看第三部分“第一次使用” |
| 换了一台电脑，电脑上还没有这个项目 | 看第四部分“在另一台电脑上使用” |
| 另一台电脑已经有同一个 Git 项目 | 看第五部分“绑定已有项目” |
| 已经设置好了，今天继续工作 | 看第六部分“每天怎么用” |
| 按钮是灰的，或者报错了 | 看第七、八部分 |

## 一、先弄清三个位置

下面一直用同一个例子。路径都是示例，请换成你自己的盘符和目录。

| 位置 | 示例 | 用来干什么 |
| --- | --- | --- |
| 电脑 A 的项目目录 | `D:\Projects\MyTool` | 在这里打开工程、改代码、提交 |
| U 盘代码库目录 | `F:\GitVault` | 集中存放多个项目，随 U 盘带走 |
| 电脑 B 的项目目录 | `C:\Code\MyTool` | 在另一台电脑上继续开发 |

```text
电脑 A                    U 盘                     电脑 B
D:\Projects\MyTool   ⇄   F:\GitVault          ⇄   C:\Code\MyTool
编辑、提交代码             保存 Git 仓库             编辑、提交代码
```

**U 盘代码库可以理解为“U 盘上的项目总目录”。** 一个代码库可以放多个项目，一般只需要创建一次。

程序会把示例项目存为 `F:\GitVault\repos\MyTool.git`。这是 Git 使用的存储目录，里面不一定能直接看到平时的源代码文件；它不是用来打开工程、直接编辑代码的目录。日常开发仍在电脑 A 或 B 的项目目录中进行。

程序所在目录与代码库目录可以分开。创建代码库要选空目录，别把装有 `GitVault.exe` 和许多 DLL 的程序目录当作新代码库。

## 二、界面上每块区域是干什么的

下面是位置示意，不是真实截图。

```text
┌──────────────────────────────────────────────────────────┐
│ GitVault        [选择已有代码库] [创建 U 盘代码库] [设置]│ ①
├──────────────────────────────────────────────────────────┤
│ 代码库名称和路径     [选择位置 ▾] 已连接 [扫描 U 盘][刷新]│ ②
├───────────────────┬──────────────────────────────────────┤
│ 仓库              │ MyTool                               │
│ [搜索框]          │ 本地工作目录             [打开目录]  │
│ [＋加入 U 盘代码库] │ U 盘中的位置                        │
│                   │                                      │
│ MyTool            │ 当前分支：main                       │ ④
│ OtherProject      │ 本地领先 / U 盘领先 / 已同步         │
│                   │                                      │
│                   │ [推送][拉取][克隆到本机][绑定已有项目]│
│                   │ 最近提交                             │
│ [恢复仓库列表]  │                                      │
│        ③          │                                      │
├───────────────────┴──────────────────────────────────────┤
│ 操作结果                         [取消操作，仅操作中出现]│ ⑤
│ ▸ 操作日志                                  [复制日志]  │
└──────────────────────────────────────────────────────────┘
```

| 区域 | 你需要关注什么 |
| --- | --- |
| ① 右上角 | 第一次用“创建 U 盘代码库”；已有代码库用“选择已有代码库”；找不到 Git 时进“设置” |
| ② 设备区域 | 确认路径是你想用的 U 盘，且显示“已连接”；换盘后可点“扫描 U 盘” |
| ③ 左侧列表 | 点击项目名称，右侧才会显示这个项目的操作；搜索框只按名称筛选列表 |
| ④ 右侧详情 | 检查本地目录、当前分支和领先状态，再决定推送还是拉取 |
| ⑤ 底部 | 等待操作结束；失败时展开“操作日志”，里面有具体原因 |

“最近提交”是当前本地分支的提交记录。第一次在新电脑上打开代码库，还没有克隆或绑定时，这里为空是正常的。

## 三、第一次使用：把电脑 A 的项目放进 U 盘

### 第 1 步：打开程序，确认项目已经使用 Git

解压整个发布包，然后双击 `GitVault.exe`。不要只复制一个 exe 文件出来运行。

这个工具传输的是 **Git 已经提交过的代码**。开始前，你的 `D:\Projects\MyTool` 应当已经是 Git 项目，而且至少做过一次提交。

如果只是一个普通代码文件夹，请先用原来的开发工具或 Git 客户端为它创建 Git 仓库并做首次提交。GitVault 当前没有“创建本地 Git 仓库”和“提交代码”按钮。

如果程序提示找不到 Git：

1. 点击右上角“设置”。
2. 在“Git 可执行文件”里保留 `git`（本机环境能找到 Git 时），或点击“浏览…”选择已安装的 `git.exe`。
3. 例如 Git 安装在默认位置时，文件可能是 `C:\Program Files\Git\cmd\git.exe`；以你电脑实际位置为准。
4. 点“确定”，等底部显示验证完成；再点“扫描 U 盘”继续。

发布包带有 .NET 运行时，但不包含 Git。如果电脑没有安装 Git，也没有便携 Git，需要先准备 Git。

### 第 2 步：创建 U 盘代码库

插上 U 盘。假设它现在是 `F:`。

第一次打开程序时，如果显示“尚未连接 U 盘代码库”，插入 U 盘后会自动识别；也可以点“扫描 U 盘”，或用“选择已有代码库”手动定位。

1. 点击右上角 **“创建 U 盘代码库”**。
2. 按下表填写。
3. 点击“确定”。

| 输入框 | 示例填写 | 说明 |
| --- | --- | --- |
| 代码库名称 | `我的代码库` | 界面上的显示名称，可自行取名 |
| 代码库目录 | `F:\GitVault` | 必须是不存在的新目录，或已经存在的空目录 |

**目录选择小提示：**“浏览…”选择的是已有文件夹。如果 `F:\GitVault` 还不存在，可以直接在输入框里填写完整路径；也可以先在资源管理器里建一个空的 `GitVault` 文件夹，再浏览选择它。

不要直接选择装有其他文件的 `F:\` 根目录。代码库只需要创建一次；如果顶部没有出现预期的代码库，请用“选择已有代码库”打开原来的目录，不要重复创建。

**做对后的结果：**顶部出现“我的代码库”、`F:\GitVault` 和“已连接”；左边还没有项目，但“＋ 加入 U 盘代码库”可以点击了。

### 第 3 步：加入你的本地项目

1. 点击左侧 **“＋ 加入 U 盘代码库”**。
2. 按下表填写。
3. 点击“确定”，等待底部不再显示操作进行中。

| 输入框 | 示例填写 | 说明 |
| --- | --- | --- |
| 本地 Git 工作区根目录 | `D:\Projects\MyTool` | 选择你平时打开工程的项目根目录 |
| 在代码库中的名称 | `MyTool` | 填名称即可，程序会自动添加 `.git` 后缀 |

选择的是 `MyTool` 项目目录，**不是**它里面的 `.git` 目录，也不是存放所有项目的 `D:\Projects` 总目录。

**做对后的结果：**左侧出现 `MyTool`；右侧显示本地目录和 U 盘目录，已绑定到这台电脑。正常情况下，当前分支会显示“已同步”。首次导入已经把已有提交复制过去，不需要再重复点一次“推送”。

未提交的文件不会导入。如果你最近改过代码但还没有提交，请在原来的工具里提交，再回来刷新、推送。

## 四、在另一台电脑上使用：先克隆一份

适用情况：电脑 B 上还没有这个项目。

### 第 1 步：打开同一个 U 盘代码库

1. 电脑 A 上的操作完成后，通过 Windows 正常弹出 U 盘。
2. 将 U 盘插到电脑 B，打开 GitVault。
3. 如果没有自动出现项目，点击右上角 **“选择已有代码库”**。
4. 选择 U 盘中的代码库目录（当初创建或自动识别的那个目录）。

例如盘符变成 `G:`，这次选 `G:\GitVault`。不要选 `G:\GitVault\repos` 或里面的 `MyTool.git`。

如果选到了普通 Git 项目目录，程序会提示“检测到本地 Git 项目”，并引导你先创建代码库、再加入项目；选到空目录时，也可以直接在现场创建。

**同一块 U 盘到了另一台电脑，不需要再次“创建 U 盘代码库”。**

### 第 2 步：选择项目并克隆

1. 点击左侧 `MyTool`。正常会显示“本机未绑定”。
2. 点击右侧 **“克隆到本机”**。
3. 按下表填写，然后点“确定”。

| 输入框 | 示例填写 | 说明 |
| --- | --- | --- |
| 目标父目录 | `C:\Code` | 这个文件夹要已经存在 |
| 新文件夹名称 | `MyTool` | 程序会在父目录下创建这个文件夹 |

最终得到的项目路径是 **`C:\Code\MyTool`**。

不要把“目标父目录”填成 `C:\Code\MyTool`，又把“新文件夹名称”填成 `MyTool`，否则会多出一层同名目录。也不要提前建好最终的 `C:\Code\MyTool`，即使是空文件夹，当前版本也会拒绝覆盖。

**做对后的结果：**右侧“本地工作目录”变为 `C:\Code\MyTool`，当前分支显示“已同步”，下面出现最近提交。点击“打开目录”能看到源代码，再用你的开发工具打开工程。

克隆只需做一次。以后这台电脑继续使用同一个目录，日常点“推送”或“拉取”即可。

## 五、如果另一台电脑已经有项目：使用“绑定”

适用情况：电脑 B 已经有一份同一 Git 项目的工作目录，不需要再克隆。

1. 打开 U 盘上的代码库。
2. 在左侧选中 `MyTool`。
3. 点击 **“绑定已有项目”**。
4. 选择电脑 B 上现有的项目根目录，例如 `C:\Code\MyTool`。
5. 等检查完成，看右侧是否显示正确的本地目录。

绑定只是告诉程序“这个 U 盘仓库对应这台电脑的哪个项目”。它不会立即覆盖本地文件，也不会自动推送或拉取。绑定完成后，继续根据右侧状态决定操作。

本地项目需要与 U 盘仓库具有共同的 Git 历史，当前分支也要同名。只复制源代码、再重新创建一个 Git 仓库，即使文件相同，也可能不能绑定。

如果提示先切换分支，请用原来的 Git 工具切到 U 盘已有的同名分支，例如 `main`，再回来绑定。

如果移动了本机项目目录，也可以重新绑定到新位置。一个 U 盘仓库在每台电脑上只记录一个本地目录；重新绑定会替换这台电脑的旧对应关系，旧目录不会被删除。

## 六、每天怎么用

### 开始工作前：先接收 U 盘里的更新

1. 插入 U 盘，打开 GitVault。
2. 确认顶部是正确的代码库，点击左侧项目。
3. 点 **“刷新”**，看“当前分支”和同步状态。
4. 如果显示 **“U 盘领先 N 次提交”**，且工作区干净，点 **“↓ 从 U 盘拉取”**。
5. 等待完成、状态变成“当前分支已同步”，再开始改代码。

如果本来就是“已同步”，无需再点拉取。

### 工作结束后：先提交，再送到 U 盘

1. 保存代码文件。
2. 在你原来的开发工具或 Git 客户端中完成 **提交（Commit）**。
3. 回到 GitVault，点 **“刷新”**。
4. 看到 **“本地领先 N 次提交”**，点 **“↑ 推送到 U 盘”**。
5. 等操作结束，并确认“当前分支已同步”，再弹出 U 盘。

**保存文件不等于 Git 提交。** 如果只保存了文件却没有提交，GitVault 不会把这些改动推送走。界面可能同时显示“当前分支已同步”和“工作区有修改”：前者比较的是已提交历史，后者说明本机还有没提交的文件。

### 要同步多个分支时

右侧“当前分支”决定本次同步哪一个分支。比如显示 `main`，推送按钮就只处理 `main`。

需要处理另一个分支时，在原来的 Git 工具中切换分支，再回来刷新。后续推送/拉取不会自动同步所有分支和标签。

如果出现“在 U 盘创建此分支”，说明本机当前分支还没有对应的 U 盘分支。确实想把它带走时，点击这个按钮即可。

## 七、看状态决定点哪个按钮

| 界面显示 | 是什么意思 | 你该怎么做 |
| --- | --- | --- |
| 本机未绑定 | 程序不知道这台电脑的项目在哪 | 没有项目就“克隆到本机”，已有项目就“绑定已有项目” |
| 当前分支已同步 | 两边当前分支的已提交历史一致 | 无需传输；另看是否有未提交修改 |
| 本地领先 3 次提交 | 电脑上有 3 个 U 盘还没有的提交 | 点“推送到 U 盘” |
| U 盘领先 2 次提交 | U 盘有 2 个电脑上还没有的提交 | 工作区干净时点“从 U 盘拉取” |
| 已分叉：本地 2 / U 盘 1 | 两边各自增加了提交，不能直接接上 | 先用其他 Git 工具整合，见下一部分 |
| U 盘没有同名分支 | 本机正在使用一个新分支 | 需要带走它时，点“在 U 盘创建此分支” |
| 工作区有修改 | 有修改、暂存或未跟踪文件尚未形成提交 | 先处理这些文件；拉取会被禁用 |
| U 盘离线 / 数据已过期 | 上一次状态不能再用于判断 | 插盘，点“扫描 U 盘”；找不到就“选择已有代码库” |
| 尚未连接 U 盘代码库 | 第一次启动，或 U 盘还没有插入 | 插入 U 盘会自动识别；也可以点“扫描 U 盘”“选择已有代码库”或“创建 U 盘代码库” |
| 刷新失败 / 操作未完成 | 当前结果不确定 | 展开底部“操作日志”查看原因，处理后刷新 |

“领先几次提交”不是“多了几个文件”。一个提交可能改动多个文件。

## 八、常见问题

### 1. “加入 U 盘代码库”为什么是灰色的？

先看顶部是否显示“已连接”。还没有创建或打开代码库时，这个按钮不能用。正在执行其他操作时，也会临时禁用。

### 2. 推送和拉取为什么都不能点？

按这个顺序看：

1. 左边有没有选中项目？
2. U 盘是否已连接？
3. 右边是否显示正确的本地目录？没有就先克隆或绑定。
4. 点刷新后是什么状态？如果已同步，两个按钮变灰是正常的。
5. 如果分叉、刷新失败或仓库状态不支持，需要先处理提示中的问题。

通常“本地领先”时只亮推送，“U 盘领先且工作区干净”时只亮拉取，不需要两个按钮同时可用。

### 3. 显示 U 盘领先，但还是不能拉取？

检查是否显示“工作区有修改”。请回开发工具处理本机修改：需要保留的可以提交或使用 Git 的 stash 临时收起；不需要的也应在确认后由你自己处理。

不要为了点亮拉取按钮，直接删除看不懂的文件。GitVault 不会替你丢弃修改，也不会自动 stash。

如果把本地修改提交了，两边可能变成“已分叉”，这时需要先整合提交。

### 4. “已分叉”怎么办？

常见原因是：电脑 A 的新提交还没拉到电脑 B，电脑 B 又独立做了新提交。

当前版本没有一键合并按钮。请用熟悉的 Git 工具把 U 盘分支抓取到本机，再进行合并或变基；处理完冲突和未完成操作后，回 GitVault 刷新，再推送整合后的分支。

如果不熟悉合并，先保留两边现状，把状态和日志提供给协助你的人。不要反复克隆覆盖原目录，也不要强制推送。

以后尽量保持“开始前先拉取，结束后提交并推送”，可以减少这种情况。

### 5. 换电脑后 U 盘变了盘符，要重新创建吗？

不需要。先点“扫描 U 盘”；如果没有识别出来，点“选择已有代码库”，选择新盘符下的原目录，例如 `G:\GitVault`。

如果顶部列表出现多个位置，请看清路径，选择实际要用的 U 盘。

### 6. 已经用命令建过 U 盘裸仓库，能直接打开吗？

“选择已有代码库”需要选择代码库总目录，不能直接选一个普通的 `MyTool.git` 文件夹。

当前版本没有任意位置裸仓库的一键导入入口。最容易操作的方式是：新建一个空代码库，再从完整的本地 Git 项目使用“加入 U 盘代码库”。先保留原来的 U 盘仓库。

左下角“恢复仓库列表”只查找当前代码库的 `repos` 目录下已有的 `.git` 裸仓库，主要用于恢复中途加入列表失败的项目，不是“打开任何 Git 仓库”的按钮。

### 7. 提示目标目录已经存在怎么办？

- **加入项目时：**当前代码库里可能已有同名项目。先看左侧是否已有该项目；正常使用无需重复导入。若目录存在但列表没有，可检查“恢复仓库列表”。
- **克隆时：**选择一个尚不存在的新文件夹名称。如果现有文件夹本来就是同一个 Git 项目，用“绑定已有项目”。

### 8. 取消了操作，或者中途拔了 U 盘怎么办？

重新插入 U 盘，打开或扫描代码库，再刷新状态。取消不代表所有动作已回滚，不能仅凭“已取消”判断数据有没有传过去。

失败可能留下 `.import-*` 或 `.gitvault-clone-*` 临时目录；日常无需操作它们。确认没有任务运行后，再根据日志检查和处理。不要直接删除原项目目录。

### 9. “恢复仓库列表”什么时候用？

主要用于这种情况：U 盘上的项目已经复制完成，但程序保存列表失败，左侧没有出现该项目。

打开对应代码库，点“恢复仓库列表”，等待完成；在日志中可查看恢复数量。这个按钮会把检查通过的项目加入列表，**不会自动绑定本机目录，也不会找回未提交的代码**。恢复后按需要绑定已有项目或克隆。

### 10. 日志从哪里看？

点击窗口最下方的“操作日志”展开。需要协助排查时，点“复制日志”，保留其中的报错部分和当时做的操作。

本机日志文件还保存在 `%LocalAppData%\GitVault`。通常直接从界面复制更方便。

### 11. 提示 LFS、子模块、浅克隆或 HEAD 未附着到分支？

这些是当前版本不支持自动同步的仓库状态，不是缺少某个按钮。请先用原来的 Git 工具处理对应状态。HEAD 未附着到分支时，通常需要先切换到一个正常的本地分支；未完成合并或变基时，需要先完成或正确结束该操作。

## 九、按钮速查表

| 按钮 | 什么时候用 | 会做什么 |
| --- | --- | --- |
| 创建 U 盘代码库 | 第一次在 U 盘上建立代码库 | 创建代码库目录与项目存储区 |
| 选择已有代码库 | 使用已建好的代码库 | 打开所选目录中的代码库 |
| 设置 | Git 找不到或要换 Git 程序 | 设置并验证 git.exe 路径 |
| 扫描 U 盘 | 插盘、换盘符、查找代码库 | 重新发现 U 盘上的代码库 |
| 刷新 | 提交、切分支后，或检查同步状态 | 抓取并比较分支；不会自动合并工作区代码 |
| ＋ 加入 U 盘代码库 | 第一次把本地项目保存到 U 盘 | 在代码库中创建项目存储，并记住本机目录 |
| 克隆到本机 | 当前电脑还没有项目 | 新建本地工作目录，并绑定它 |
| 绑定已有项目 | 当前电脑已经有同一 Git 项目 | 检查历史并记录对应目录 |
| ↑ 推送到 U 盘 | 本地领先 | 把当前分支的已提交内容送到 U 盘 |
| ↓ 从 U 盘拉取 | U 盘领先且本地工作区干净 | 快进更新本地当前分支和文件 |
| 打开目录 | 想用资源管理器查看本机项目 | 打开本地工作目录 |
| 恢复仓库列表 | 项目存储已存在但未加入列表 | 检查并恢复列表登记 |
| 取消操作 | 当前传输需要停止 | 请求终止任务，之后需刷新复核 |
| 复制日志 | 排查错误 | 复制当前界面的近期操作记录 |
