## 自动化验证

使用真实 Git 仓库，覆盖下列场景：

1. 电脑 A 导入 → B 克隆 → A 推送 → B 拉取 → B 推送 → A 拉取，最终提交 OID 和文件一致。
2. 不改变已有 origin、usb 和 upstream；未提交文件不会被传输。
3. 两边分叉时拒绝普通推送和快进拉取，不改写任一端提交。
4. 工作区有修改时禁止拉取，文件内容和本地 HEAD 保持不变。
5. 新建同名分支、删除远端分支后的缓存清理，用户 push.followTags 配置不会导致意外推标签。
6. Vault 改路径后身份不变；原位置被不同 Vault 替换时拒绝传输。
7. 无共同历史的项目拒绝绑定。
8. 空仓库、Detached HEAD、未完成合并及浅克隆具有明确的不支持状态。
9. 当前提交的 LFS 属性和子模块被识别，不显示为完整迁移成功。
10. 接收端 hook 拒绝推送时返回真实错误，远端 HEAD 不变。
11. 导入或克隆不覆盖已有目录。
12. 未登记裸仓库可恢复，重复恢复不产生重复项。
13. 清单只读造成实际登记失败后，源项目和完整裸仓库保留，可恢复登记。
14. 首次导入保留本地分支和标签，后续推送只更新当前分支。
15. 清单路径穿越、缺失字段与损坏设置不能静默接受或覆盖。
16. 远端缺失时刷新失败；运行中的 Git 能被取消并终止。

最终 Release 测试结果：**16 项通过，0 项失败，0 项跳过**，用时约 1 分 47 秒。原始结果位于 artifacts/TestResults/core.trx。测试日志不包含到第三方 Git 平台的传输。
